# wiki-lint

## 1. 結構檢查（腳本）

在 wiki 根目錄（`my-wiki/`）執行：

```bash
python3 .claude/skills/wiki-lint/scripts/lint.py
```

檢查項目：

| # | 項目 | 說明 |
|---|---|---|
| 1 | 斷鏈 | `[[path]]` 指向不存在的 `wiki/path.md` |
| 2 | 孤兒頁 | 除 index.md 外沒有任何頁面連入 |
| 3 | index 不一致 | 頁面存在但 index.md 沒列；或 index 列了但頁面不存在 |
| 4 | frontmatter | 缺 `type` / `title` / `sources` / `updated`；source 頁另缺 `raw` |
| 5 | raw 完整性 | raw/ 檔案 MD5 與 `.raw-manifest.md5` 不符、缺檔、或有未登記檔 |

腳本以 exit code 1 表示有問題。第 5 項若報錯：**不得修改 raw/**，立刻告知人類。

## 2. 內容檢查（LLM 判讀）

逐頁閱讀（或抽查大量頁面時優先看本次 ingest 動到的頁），檢查：

| # | 項目 | 怎麼查 |
|---|---|---|
| 6 | 數字缺頁碼 | 含數字、百分比、實驗結果、引號引述的句子，是否有 `p.N` / `§N` / `#章節` |
| 7 | 未標爭議 | 不同頁對同一件事說法不同，卻沒有 ⚠️ 爭議區塊 |
| 8 | 缺頁概念 | 在 ≥3 頁被提到、卻沒有自己 concept/entity 頁的術語（可用 grep 統計） |
| 9 | 缺白話解釋 | concept 頁沒有「白話解釋」小節或沒有比喻 |
| 10 | 觀點混雜 | 綜合判斷、推論沒有用「🧭 wiki 觀點」標示，混在來源主張中 |

另可順帶提出：值得補的新來源、值得研究的新問題、過時說法。

## 3. 處理與記錄

1. 能直接修的就修（斷鏈、index 缺項、缺頁碼可回 raw 查）。
2. 需要人類判斷的（爭議怎麼下觀點、要不要刪頁）列出來問。
3. 修完再跑一次腳本，確認結構檢查通過。
4. log.md 追加：

```markdown
## [YYYY-MM-DD] lint | <時機：批次 N 後 / 簡報前 / 手動>
- 結構：<各項問題數 → 修正後>
- 內容：<發現與處理>
- 待人類決定：…
```
